Intent sourcing, two peers

Two peers hold the same record and edit it while disconnected. Every commit stores its intent, a deterministic program, and the effect the program had. When the peers sync, programs are re-executed against the common base: if they commute there is nothing to merge; if not, a reconciliation program is written and the disagreement is classified. Press “verify” on any commit to re-run its program and compare the effect.

Four things to try, in order

  1. Semantic rebase. Peer A sets inches to 70. Peer B runs the exact lens (still on 68). Sync. The programs don't commute, but one ordering satisfies both postconditions, so a reconcileByOrdering merge commit appears and B's derivation is flagged as having produced a different effect on the new base.
  2. Translation discrepancy. Both peers run a lens, A exact and B rounded. Sync. Same source, different programs: the discrepancy stays open and the latest value is kept.
  3. Derived vs authored. Peer A runs a lens, peer B types cm by hand. Sync. The authored value wins by policy and heightCm becomes unowned.
  4. Destroy vs edit. Peer A sets inches, peer B destroys with reason purged. Sync. These commute, so no merge commit; the tombstone carries its sticky reason.

The prompt box does the two-step: try make me 6 feet tall. A canned planner turns it into setHeightInches(72), shown as a transaction whose message is the prompt, with the planning step marked attested and the program marked reproducible.

Discrepancies

None yet. Try: peer A sets inches to 70, peer B derives cm from the old inches, then sync. Or derive cm on both peers with different lenses.
